# Сражения: проверка на продовой БД за 2026-11-11

Источник: `C:\SE\prod\watcher-2026-11-11.db` (~456 МБ). Исходная БД открывалась SQLite в `mode=ro`; для запуска C#-детектора сделана отдельная согласованная копия через SQLite backup. Продовые файлы и сервер не изменялись.

## Что есть в данных

- 24 070 строк `damage`, включая 5 863 строки выстрелов без цели; 18 207 строк попаданий, распила, убийств и разрушений.
- Время — UTC epoch milliseconds. События свёрнуты за 2 секунды по атакующему, оружию и цели.
- `attacker` — identity атакующего, `attacker_entity` — его персонаж/грид; `victim` — владелец повреждённого блока/персонажа, `target` — грид/персонаж. Это **не обязательно пилот повреждённого корабля**.
- `weapon` содержит тип урона и определение источника, например `Bullet:LargeRailgun`, `Explosion:Missile`, `Deformation:grid`. Это не достоверная оценка стоимости потерь.
- `relation` содержит отношение в момент события, но **фракции не сохранены**. Из `enemy` нельзя восстановить принадлежность к фракциям. В новой версии сохраняются `attacker_faction` и `victim_faction`; старые записи остаются неизвестными, без подмены текущей фракцией.
- Очень много урона без установленного источника: только `hit / none / unknown` — ~199,6 млн. Нельзя автоматически приписывать его конкретному противнику.

## Текущий детектор: автоматические границы (v2)

После уточнения требований границы больше не задаются диапазоном страницы и не требуют ручного выбора порогов.

- Попадания по врагам/нейтралам идентифицируют бой. Связанный урон участникам и их объектам (включая урон без установленного источника) продлевает его. Временные цепочки неизвестного урона могут быть восстановлены и до первого идентифицированного вражеского попадания; цепочки вообще без вражеского/нейтрального урона боями не считаются.
- **120 секунд без нового связанного урона — бой окончен.** `end` — последний урон, `endedAt` — момент завершения после тишины. До его наступления `ongoing=true`, `endedAt=null`.
- Не продлевают бой собственный распил/урон, погода, звери, выстрелы без цели и события разрушений/смертей без нового урона. Неоднозначный сопутствующий урон не объединяет два боя.
- Диапазон `from/to` только отбирает бои. Детектор читает полные дни и при необходимости автоматически расширяет поиск в соседние суточные БД, пока не найдёт тишину с обеих сторон. Защитный предел — 31 сутки, при нём возвращаются флаги неполных границ.
- Пространственная связь остаётся до 5 км, чтобы не объединять одновременные бои на разных концах мира. В UI больше нет ручных настроек паузы/радиуса.

## Первичный детектор v1 (исторический разбор)

Страница `/battles.html`, API `/api/battles?from=...&to=...&gap=90&radius=5000`, подробности — тот же запрос с `battle=<id>`.

1. Основа боя — положительный `hit` или `grind` с отношением `enemy` либо `neutral`, без зверей с любой стороны. Выстрелы без цели, погода, собственный распил и friendly fire бой не начинают.
2. Попадания объединяются в компоненты связности по времени и месту: разрыв **не более 90 секунд**, расстояние **не более 5 км**. Временные и пространственные пороги настраиваются на странице. Новое попадание может объединить две ранее отдельные компоненты.
3. Начало и конец — первое и последнее попадание основы, а не искусственное добавление 90 секунд к длительности. Последовательная перестрелка может длиться сколько угодно, пока есть связующая цепочка попаданий.
4. Остальной урон, распил, убийства и разрушения — контекст. Он добавляется лишь при близости к **единственному** бою, во временных границах боя ±2 секунды. Контекст не продлевает бой. Неоднозначное событие не учитывается ни в одном, а не дублируется.
5. Бои могут пересекать границу суток; запрос читает все суточные файлы интервала. У края выбранного интервала выводится предупреждение о возможной обрезке. Для полного отчёта нужно расширить интервал (максимум 7 суток).
6. Не все найденные компоненты — крупные сражения: одиночное попадание тоже эпизод. Погоня дальше радиуса или пауза дольше порога разделяют бой; несколько близких перестрелок могут слиться. Общий identity не склеивает события в разных частях мира.

Идентификаторы в отчётах передаются строками: 64-битные SE identity/entity IDs не помещаются точно в JavaScript Number. Фракция сохраняется как `FactionId|[TAG] Name`; `NULL` означает «неизвестно», пустая строка — подтверждённое отсутствие фракции. Снимок берётся при создании двухсекундного агрегата.

## Воспроизведение текущего детектора v2

Собрать `SentisWatcher.sln`, сделать копию БД в **отдельный временный каталог**, затем:

```powershell
.\tools\battle-report.ps1 -CopyFolder C:\Temp\watcher-copy `
  -From 1794355200000 -To 1794441599999 -Output C:\Temp\battles.json
# Пауза по умолчанию 120 с. Для воспроизведения только порога старого разбора: -Gap 90.

.\tools\battle-report.ps1 -CopyFolder C:\Temp\watcher-copy `
  -From 1794355200000 -To 1794441599999 `
  -Battle '1794426053118:19757' -Output C:\Temp\battle-details.json
```

**Не передавать продовый каталог в `CopyFolder`:** `WatcherStore` имеет фоновую очистку по retention. Инструмент предназначен только для офлайн-копий. Сам веб-детектор использует read-only соединения и не мигрирует старые БД при просмотре.
